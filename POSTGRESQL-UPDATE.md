# PostgreSQL и показ пароля — 5 ноября 2026

## Изменения

- Вход, регистрация и смена пароля используют общий PasswordInput. Кнопка переключает видимость только введённого значения; по умолчанию пароль скрыт. Поддержаны русский и кыргызский языки, клавиатура и aria-pressed. Кнопка не отправляет форму.
- Рабочий backend переведён на node-postgres (`pg`). Значения передаются параметрами; SQL-литералы и комментарии не изменяются при замене placeholders. Транзакции используют одно выделенное соединение.
- Схема 14 таблиц переведена на PostgreSQL: identity, jsonb, проверяемые enum-значения, генерируемое поле, индексы, внешние ключи и timestamptz. DATE остаётся строкой календарной даты; сеансы БД используют Asia/Bishkek.
- Переписаны MySQL-специфичные DATE_ADD, CURDATE, DATE_FORMAT, INSERT IGNORE, ON DUPLICATE KEY, IF и UPDATE JOIN. Обработчики дубликатов учитывают PostgreSQL SQLSTATE 23505.
- Добавлен скрипт одноразового переноса MySQL → пустая PostgreSQL с проверкой числа строк, сохранением ID/хешей паролей и обновлением последовательностей. Он не изменяет исходную MySQL, не передаёт данные в GitHub и откатывает целевую транзакцию при ошибке. `mysql2` нужен только скрипту переноса и находится в devDependencies.
- DEPLOY.md и .env.example обновлены для PostgreSQL. На сервере получателя нужен отдельный PostgreSQL; его доступы и секреты на GitHub не публикуются.

## Проверки

- 25 клиентских наборов / 42 теста прошли; production build собран.
- 16 серверных тестов прошли, в том числе интеграционный сценарий на настоящем локальном PostgreSQL: повторное создание схемы, регистрация с фото, одобрение пользователя, создание/делегирование задач, контроль доступа, повторное чтение уведомлений, отправка и приём отчёта, повторный запрос анализа, обращение по оценке, архив, идеи, защита от повторного начисления, рейтинг, изменение профиля и отзыв токена после смены пароля.
- Unit-тесты проверяют безопасную передачу параметров, возвращаемые ID/количество строк и транзакционное соединение.
- Backend npm audit --omit=dev: 0 известных уязвимостей на дату проверки. Это не гарантия полной безопасности; ранее зафиксированные клиентские зависимости и другие ограничения остаются в SECURITY-REVIEW.md.
- Перенос локальной рабочей базы выполнен с проверкой количества записей в каждой из 14 таблиц. Фотографии и документы сохранены локально. PostgreSQL слушает только loopback; приложение использует отдельную роль без superuser. На сервер получателя эти данные не копировались.

## Установка у получателя

Использовать актуальные backend/, frontend/, database/ и DEPLOY.md из ветки updated-site. До замены рабочей MySQL остановить записи, сделать резервную копию, выполнить перенос в пустую PostgreSQL и проверить результат. Наличие обновления на GitHub не означает установку на удалённый сервер.
